# Groupes Active Directory

## 1. Introduction aux groupes

### 1.1. Qu'est-ce qu'un groupe Active Directory ?

Un groupe Active Directory **est un conteneur qui permet de rassembler et de gérer plusieurs objets (utilisateurs, ordinateurs ou autres groupes) comme une seule entité**. Il permet de :
- Gérer les permissions pour plusieurs utilisateurs simultanément
- Simplifier l'administration des accès
- Organiser les utilisateurs par fonction ou service
- Réduire la complexité de la gestion des droits

### 1.2. Objectifs Pédagogiques

À la fin de ce chapitre, vous serez capable de :
1. Comprendre et utiliser les différents types de groupes (sécurité et distribution)
2. Maîtriser les étendues de groupe (domaine local, global, universel)
3. Créer et gérer des groupes via l'interface graphique et PowerShell
4. Implémenter les bonnes pratiques de gestion des groupes

> **Note** : La gestion efficace des groupes est essentielle pour maintenir une structure de sécurité cohérente dans Active Directory.

### 1.3. Types de groupes

#### Qu'est-ce qui détermine le type d'un groupe ?
Le type d'un groupe **définit sa fonction principale dans l'infrastructure Active Directory**. Il existe deux types principaux :

#### Groupes de sécurité
**Objectif principal** : Gestion des accès et des permissions

**Caractéristiques** :
- Peuvent recevoir des permissions sur les ressources
- Gèrent l'accès aux dossiers, imprimantes, etc.
- Peuvent contenir tous types d'objets AD

**Exemple pratique** :
```
Groupe : COMPTA-ACCES
Type : Sécurité
Utilisation : Contrôle l'accès aux dossiers comptables
```

#### Groupes de distribution
**Objectif principal** : Communication et messagerie

**Caractéristiques** :
- Dédiés à la messagerie électronique
- Ne peuvent pas recevoir de permissions
- Utilisés avec Exchange Server

**Exemple pratique** :
```
Groupe : INFO-NEWSLETTER
Type : Distribution
Utilisation : Envoi de newsletters internes
```

### 1.4. Étendues de groupe

#### Qu'est-ce que l'étendue d'un groupe ?
L'étendue d'un groupe **détermine sa portée d'utilisation dans l'infrastructure Active Directory**. Elle influence où le groupe peut être utilisé et qui peut en être membre.

#### Domaine local
**Objectif** : Attribuer des permissions dans un domaine spécifique

**Caractéristiques** :
- Utilisés pour les permissions locales
- Acceptent des membres de n'importe quel domaine
- Portée limitée à leur domaine

**Exemple pratique** :
```
Groupe : DL-SERVEUR-ADMIN
Portée : Domaine local
Utilisation : Accès administratif aux serveurs locaux
```

#### Global
**Objectif** : Organiser les utilisateurs par fonction ou service

**Caractéristiques** :
- Membres limités à un seul domaine
- Utilisables dans tout l'arbre de domaines
- Idéaux pour les groupes métier

**Exemple pratique** :
```
Groupe : G-COMPTABILITE
Portée : Global
Utilisation : Regroupe tous les comptables
```

#### Universel
**Objectif** : Gestion à l'échelle de la forêt

**Caractéristiques** :
- Membres de toute la forêt Active Directory
- Utilisables partout dans la forêt
- Impact sur la réplication (catalogue global)

**Exemple pratique** :
```
Groupe : U-DIRECTION
Portée : Universel
Utilisation : Accès direction dans toute l'entreprise
```

> **Important** : Le choix de l'étendue impacte directement les performances et la sécurité. Utilisez les groupes universels avec parcimonie en raison de leur impact sur la réplication.

## 2. Création et gestion des groupes

### 2.1. Création via l'interface graphique
#### Création d'un groupe
1. Ouvrez "Utilisateurs et ordinateurs Active Directory"
2. Clic droit sur l'OU -> Nouveau -> Groupe
3. Configurez :
   - Nom : COMPTA-Users
   - Étendue : Global
   - Type : Sécurité

#### Ajout de membres
1. Double-clic sur le groupe
2. Onglet "Membres"
3. Ajoutez les utilisateurs ou groupes

### 2.2. Création via PowerShell

#### Création de groupes
```powershell
# Groupe de sécurité global
New-ADGroup -Name "COMPTA-Users" `
           -GroupScope Global `
           -GroupCategory Security

# Groupe de sécurité domaine local
New-ADGroup -Name "COMPTA-Resources" `
           -GroupScope DomainLocal `
           -GroupCategory Security
```

#### Gestion des membres
```powershell
# Ajouter un membre
Add-ADGroupMember -Identity "COMPTA-Users" `
                 -Members "jdupont"

# Lister les membres
Get-ADGroupMember -Identity "COMPTA-Users"
```

## 3. Stratégie de groupes recommandée

### 3.1. Modèle AGDLP

#### Composants
- **A** - Account (Compte utilisateur)
- **G** - Global Group (Groupe global - par fonction)
- **DL** - Domain Local Group (Groupe local - pour les ressources)
- **P** - Permissions (sur les ressources)

#### Exemple d'application
```
Utilisateur → Groupe Global → Groupe Local → Permissions
(jdupont) → (COMPTA-Users) → (COMPTA-Resources) → (Accès dossier)
```

### 3.2. Exercice pratique - Mise en place AGDLP

#### Création des groupes

Groupes globaux (rôles) :
- COMPTA-Users
- COMPTA-Managers

Groupes domaine local (ressources) :
- COMPTA-Files-RW
- COMPTA-Files-RO

#### Configuration
1. Ajoutez les utilisateurs aux groupes globaux
2. Ajoutez les groupes globaux aux groupes locaux
3. Attribuez les permissions aux groupes locaux

## 4. Exercices pratiques

### 4.1. Structure départementale

#### Objectif
Créer une structure de groupes pour le département RH

#### Groupes à créer

Groupes globaux :
- RH-Users
- RH-Managers
- RH-Interns

Groupes domaine local :
- RH-Files-Full
- RH-Files-Modify
- RH-Files-Read

#### Test de la structure
```powershell
# Vérification de la structure
Get-ADGroup -Filter "Name -like 'RH-*'" | 
Select-Object Name, GroupScope
```

### 4.2. Imbrication de groupes

#### Scénario
Gestion des accès aux applications

#### Structure des groupes
```
APP-PayrollSystem-Users
├── COMPTA-Users
└── RH-Users

APP-PayrollSystem-Admins
├── COMPTA-Managers
└── RH-Managers
```

#### Implémentation
```powershell
# Création des groupes d'applications
New-ADGroup -Name "APP-PayrollSystem-Users" -GroupScope DomainLocal
New-ADGroup -Name "APP-PayrollSystem-Admins" -GroupScope DomainLocal

# Ajout des groupes départementaux
Add-ADGroupMember -Identity "APP-PayrollSystem-Users" `
                 -Members "COMPTA-Users","RH-Users"
```

## 5. Bonnes pratiques

### 5.1. Nommage
- Préfixe indiquant le type (G_, DL_)
- Nom descriptif de la fonction
- Suffixe indiquant le niveau d'accès (_RW, _RO)

### 5.2. Structure
- Évitez plus de 5 niveaux d'imbrication
- Documentez la hiérarchie des groupes
- Utilisez AGDLP ou AGUDLP

### 5.3. Sécurité
- Auditez régulièrement les membres
- Évitez les appartenances directes aux groupes privilégiés
- Documentez les changements

## 6. Exercice final - Migration de structure

### 6.1. Scénario
Migrer d'une structure plate vers AGDLP

#### État actuel
- Utilisateurs directement dans groupes ressources
- Pas de distinction rôle/ressource

#### Plan de migration
1. Créer la nouvelle structure
2. Mapper les utilisateurs aux groupes globaux
3. Mapper les groupes globaux aux groupes locaux
4. Tester les accès
5. Retirer les anciennes permissions

#### Validation
```powershell
# Vérification des appartenances
Get-ADPrincipalGroupMembership "utilisateur"

# Vérification des accès
Test-Path "\\serveur\partage"
```
