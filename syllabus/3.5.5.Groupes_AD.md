# Groupes Active Directory

## 1. Introduction aux groupes

Les groupes dans Active Directory permettent de :
- Gérer les permissions pour plusieurs utilisateurs
- Simplifier l'administration
- Organiser les utilisateurs par fonction ou service

### 1.1. Types de groupes

1. **Groupes de sécurité**
   - Peuvent recevoir des permissions
   - Utilisés pour l'accès aux ressources
   - Peuvent contenir des utilisateurs et d'autres groupes

2. **Groupes de distribution**
   - Utilisés uniquement pour la messagerie
   - Ne peuvent pas recevoir de permissions
   - Principalement pour Microsoft Exchange

### 1.2. Étendues de groupe

1. **Domaine local**
   - Utilisés pour attribuer des permissions
   - Peuvent contenir des membres de n'importe quel domaine
   - Ne peuvent être utilisés que dans leur domaine

2. **Global**
   - Contiennent des utilisateurs d'un seul domaine
   - Peuvent être utilisés dans tout l'arbre de domaines
   - Recommandés pour regrouper les utilisateurs

3. **Universel**
   - Peuvent contenir des membres de toute la forêt
   - Peuvent être utilisés dans toute la forêt
   - Attention à la réplication !

## 2. Création et gestion des groupes

### 2.1. Création via l'interface graphique

1. **Création d'un groupe de sécurité**
   ```
   a. Ouvrez "Utilisateurs et ordinateurs Active Directory"
   b. Clic droit sur l'OU -> Nouveau -> Groupe
   c. Configurez :
      - Nom : COMPTA-Users
      - Étendue : Global
      - Type : Sécurité
   ```

2. **Ajout de membres**
   ```
   a. Double-clic sur le groupe
   b. Onglet "Membres"
   c. Ajoutez les utilisateurs ou groupes
   ```

### 2.2. Création via PowerShell

1. **Création de groupes**
   ```powershell
   # Groupe de sécurité global
   New-ADGroup -Name "COMPTA-Users" `
               -GroupScope Global `
               -GroupCategory Security
   
   # Groupe de sécurité domaine local
   New-ADGroup -Name "COMPTA-Resources" `
               -GroupScope DomainLocal `
               -GroupCategory Security
   ```

2. **Gestion des membres**
   ```powershell
   # Ajouter un membre
   Add-ADGroupMember -Identity "COMPTA-Users" `
                     -Members "jdupont"
   
   # Lister les membres
   Get-ADGroupMember -Identity "COMPTA-Users"
   ```

## 3. Stratégie de groupes recommandée

### 3.1. Modèle AGDLP

1. **A** - Account (Compte utilisateur)
2. **G** - Global Group (Groupe global - par fonction)
3. **DL** - Domain Local Group (Groupe local - pour les ressources)
4. **P** - Permissions (sur les ressources)

Exemple :
```
Utilisateur → Groupe Global → Groupe Local → Permissions
(jdupont) → (COMPTA-Users) → (COMPTA-Resources) → (Accès dossier)
```

### 3.2. Exercice pratique - Mise en place AGDLP

1. **Création des groupes**
   ```
   Globaux (rôles) :
   - COMPTA-Users
   - COMPTA-Managers
   
   Domaine Local (ressources) :
   - COMPTA-Files-RW
   - COMPTA-Files-RO
   ```

2. **Configuration**
   ```
   a. Ajoutez les utilisateurs aux groupes globaux
   b. Ajoutez les groupes globaux aux groupes locaux
   c. Attribuez les permissions aux groupes locaux
   ```

## 4. Exercices pratiques

### 4.1. Structure départementale

1. **Objectif** : Créer une structure de groupes pour le département RH

2. **Groupes à créer**
   ```
   Globaux :
   - RH-Users
   - RH-Managers
   - RH-Interns
   
   Domaine Local :
   - RH-Files-Full
   - RH-Files-Modify
   - RH-Files-Read
   ```

3. **Test**
   ```powershell
   # Vérification de la structure
   Get-ADGroup -Filter "Name -like 'RH-*'" | 
   Select-Object Name, GroupScope
   ```

### 4.2. Imbrication de groupes

1. **Scénario** : Gestion des accès aux applications

2. **Structure**
   ```
   APP-PayrollSystem-Users
   ├── COMPTA-Users
   └── RH-Users
   
   APP-PayrollSystem-Admins
   ├── COMPTA-Managers
   └── RH-Managers
   ```

3. **Implémentation**
   ```powershell
   # Création des groupes d'applications
   New-ADGroup -Name "APP-PayrollSystem-Users" -GroupScope DomainLocal
   New-ADGroup -Name "APP-PayrollSystem-Admins" -GroupScope DomainLocal
   
   # Ajout des groupes départementaux
   Add-ADGroupMember -Identity "APP-PayrollSystem-Users" `
                     -Members "COMPTA-Users","RH-Users"
   ```

## 5. Bonnes pratiques

1. **Nommage**
   - Préfixe indiquant le type (G_, DL_)
   - Nom descriptif de la fonction
   - Suffixe indiquant le niveau d'accès (_RW, _RO)

2. **Structure**
   - Évitez plus de 5 niveaux d'imbrication
   - Documentez la hiérarchie des groupes
   - Utilisez AGDLP ou AGUDLP

3. **Sécurité**
   - Auditez régulièrement les membres
   - Évitez les appartenances directes aux groupes privilégiés
   - Documentez les changements

## 6. Exercice final - Migration de structure

### 6.1. Scénario
Migrer d'une structure plate vers AGDLP

1. **Analyse**
   ```
   Structure actuelle :
   - Utilisateurs directement dans groupes ressources
   - Pas de distinction rôle/ressource
   ```

2. **Plan de migration**
   ```
   a. Créer la nouvelle structure
   b. Mapper les utilisateurs aux groupes globaux
   c. Mapper les groupes globaux aux groupes locaux
   d. Tester les accès
   e. Retirer les anciennes permissions
   ```

3. **Validation**
   ```powershell
   # Vérification des appartenances
   Get-ADPrincipalGroupMembership "utilisateur"
   
   # Vérification des accès
   Test-Path "\\serveur\partage"
   ```
